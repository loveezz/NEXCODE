# Подсистема входа и идентификации

## Студент

`POST /api/auth/login` принимает `{full_name,group_name,code?}`. ФИО ограничено 150 Unicode-символами, группа — 20. Сервер выполняет NFC-нормализацию, схлопывает Unicode-пробелы, переводит в верхний регистр и отклоняет управляющие/невидимые символы. Регистр и лишние пробелы не создают дублей. Для групп с приглашениями код — 4–8 латинских букв/цифр, регистр не важен.

При свободном вводе неизвестная группа создаётся автоматически; при выборе из справочника она не допускается. Без кодов ищется одна запись по нормализованным ФИО + группе. С кодами имя, группа и код должны соответствовать одной записи списка. Полные тёзки получают разные invite_code_id и независимые профили. При включении кодов один существующий профиль с тем же ФИО/группой привязывается к первому подходящему приглашению, сохраняя прогресс.

Ошибка для неизвестной записи в группе с кодами, неверного кода или заблокированного аккаунта одинакова: 401, «Не удалось войти. Проверьте ФИО, группу и код». Пустые и слишком длинные поля дают 400. Любой публичный вход, включая служебный, ограничен 10 попытками/минуту/IP; превышение даёт 429 и Retry-After.

`GET /api/auth/options` публикует только режим, названия групп, требование кода и дату окончания семестра. ФИО, коды и число студентов публично не выдаются.

## Сессии и дата семестра

Каждый вход создаёт новый UUIDv4 и строку sessions. users.session_uuid содержит последний выданный UUID; остальные устройства авторизуются через таблицу sessions и продолжают работать. Cookie `nexcode_session`: httpOnly, SameSite=Lax, Path=/, Expires/Max-Age до конца семестра, Secure при HTTPS. JWT больше не используется.

Преподаватель задаёт дату в «Группы и вход → Срок доступа студентов». Первоначальное значение берётся из SEMESTER_END либо вычисляется как ближайшее 31 января/30 июня. После этого настройка в SQLite является основной: перезапуск не перезаписывает её из .env. Допускается дата от текущего дня до одного года вперёд. Последняя секунда выбранного дня вычисляется в APP_TIMEZONE, с учётом часового пояса.

Изменение даты обновляет существующие ученические sessions.expires. Cookie обновляется при следующем авторизованном запросе браузера. Браузер с уже удалённой/истёкшей cookie должен войти заново; прогресс останется. Служебные сессии действуют сутки и не зависят от даты семестра.

Выход отзывает только текущий UUID и удаляет cookie. Преподаватель отдельно завершает все сессии студента либо группы. Переключение требования кода отзывает старые сессии группы. Блокировка отзывает сессии и запрещает новый вход. Срок, роль и блокировка проверяются сервером на каждом запросе.

## Группы, списки и журнал

`GET/PUT /api/teacher/identity` — режим и semester_end. `POST /api/teacher/groups` и `PUT /api/teacher/groups/:id` — название и invite_required. Изменение названия переносит профили группы. Отключать коды при уже существующих полных тёзках нельзя, чтобы не смешать их данные.

`POST /api/teacher/groups/:id/invites` принимает `{students:[{full_name,code}]}`. До 200 записей на запрос, все коды уникальны во всей платформе. Импорт атомарный и добавляющий: повтор той же пары безопасен; использование кода с другим ФИО отклоняется. В интерфейсе можно вставить строки «ФИО;КОД», открыть JSON и скачать CSV кодов для выдачи студентам. [Пример](../examples/invites.json). Коды доступны только преподавателям и администраторам; не публикуйте файл со списком.

`DELETE /api/teacher/groups/:id/sessions` и `DELETE /api/teacher/students/:id/sessions` сохраняют данные обучения. `GET /api/teacher/login-events?group=...&student_id=...&before=...` возвращает до 100 записей и next_before для дальнейших страниц. Фильтр студента включает отказы с совпавшими ФИО/группой; такой отказ не доказывает, кто именно пытался войти.

Успешный вход атомарно сохраняет сессию, последний IP/время и событие журнала. Отказы тоже сохраняются. slog пишет JSON с полями time, ip, full_name, group, result и kind в LOG_PATH (Docker: /logs/nexcode.log). Пароли, коды и UUID в журнал не попадают. Для неверного JSON/превышения лимита неизвестные поля могут оставаться пустыми. Backend доверяет forwarded IP только из TRUSTED_PROXY_CIDRS; gateway перезаписывает заголовок действительным адресом соединения.

## Служебные аккаунты

`POST /api/auth/staff/login` принимает `{login,password}`. Сотрудник имеет отдельную запись users и bcrypt-хэш в staff_credentials. Полей password_hash и email в users нет. Студенческий UUID не может авторизовать служебную роль, даже если роль изменена непосредственно в БД. Создание/повышение ученического профиля до сотрудника через публичный вход или панель заблокировано.

Первый администратор задаётся ADMIN_LOGIN и ADMIN_PASSWORD_HASH. Дополнительных сотрудников задают в JSON-файле конфигурации, монтируемом в `/config`:

```json
[
  {"login":"teacher","full_name":"Петрова Анна Сергеевна","role":"teacher","password_hash":"<bcrypt hash>"}
]
```

Создайте приватный `config/staff.json` по [шаблону](../config/staff.example.json), установите `STAFF_ACCOUNTS_FILE=/config/staff.json` и перезапустите backend. Для bcrypt есть `backend/cmd/hash-password`: принимает пароль через stdin, выводит только хэш. Его можно запускать через Go либо Docker:

```sh
docker compose run --rm --no-deps --entrypoint hash-password backend
```

В .env заключайте bcrypt в **одинарные кавычки**, чтобы Compose не интерполировал `$`. Разрешены роли teacher/admin; bcrypt cost 10–16 (генератор использует 12). При повторном запуске конфигурация обновляет заданные аккаунты; смена хэша или роли отзывает их сессии. Отсутствующий в файле сотрудник не удаляется автоматически. Последнего активного администратора понизить/заблокировать нельзя.

Восстановления по e-mail и публичной смены пароля нет. Администратор заменяет хэш в конфигурации и перезапускает backend. Настройки ролей из конфигурации применятся снова при рестарте; учитывайте это при изменениях через интерфейс.

## Миграция

При обнаружении старой таблицы users с password_hash создаётся согласованная SQLite-копия `*.before-identity-v2-<timestamp>.bak` с правами владельца. Затем транзакционно создаются новая users, группы и таблицы служебных учётных данных. ID, черновики, отправки, блокировки и даты регистрации сохраняются. Старые студенческие пароли, токены сброса и JWT-сессии удаляются из рабочей схемы. Резервная копия содержит старые данные — храните её приватно.

У старых студентов группы отсутствовали. Их профили помещаются в группу **АРХИВ** с нормализованными ФИО. При совпадении полного имени добавляется `(#id)`, без слияния истории. Чтобы войти в прежний профиль, используйте именно это ФИО и группу; они видны преподавателю. Новый вход с другой группой создаст другой профиль. Автоматически приписать старые записи к реальным учебным группам без исходного списка нельзя.

Setup также заменяет ADMIN_PASSWORD в старой .env на bcrypt-хэш того же пароля. Повторные миграции безопасны и не создают копию заново. Перед обновлением действующего сервера дополнительно сохраните резервную копию его томов.
