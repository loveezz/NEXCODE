# Формат автотестов JSON Lines

Одна непустая строка — один JSON-объект; пустые строки разрешены. Код решения выполняется заново для каждого теста. Формат stdin/stdout, без проверки именованных функций.

```jsonl
{"stdin":"2\n3\n","stdout":"5\n"}
{"stdin":"-5\n5\n","stdout":"0\n","compare":"exact","timeout_ms":1000}
```

| Поле | Тип | Назначение |
|---|---|---|
| `stdin` | string, обязательно | Стандартный ввод; перевод строки — `\n` |
| `stdout` | string, обязательно | Ожидаемый stdout |
| `compare` | `trim` / `exact` | По умолчанию `trim` |
| `timeout_ms` | integer | 1–5000 мс для отдельного теста; 0 или отсутствие — ограничение упражнения |
| `files` | object, необязательно | Учебные текстовые файлы до запуска: имя → содержимое |
| `expected_files` | object, необязательно | Ожидаемые файлы после запуска; обязательны наличие и совпадение содержимого |
| `denied_files` | string[], необязательно | Имена учебных файлов, доступ к которым вызывает PermissionError |

Пример проверки файла:

```jsonl
{"stdin":"","stdout":"","files":{"measurements.txt":"45\n120\n"},"expected_files":{"report.txt":"120\n"}}
```

Имена — относительные, до 100 символов: латинские буквы, цифры, точка, дефис и
подчёркивание; пути и каталоги запрещены. До 16 файлов, 32 КБ на файл и 64 КБ на
набор. Файлы виртуальные и не дают доступа к файловой системе сервера. В отчёте
results также возвращаются input_files, files и expected_files.

`trim` удаляет только пробельные символы в начале и конце всего вывода. Внутренние пробелы сохраняются. `exact` учитывает пробелы и финальный перевод строки. В обоих режимах CRLF нормализуется в LF. Код возврата должен быть 0; таймаут и превышение вывода всегда означают провал, даже если напечатанный ответ совпал. stderr сохраняется отдельно.

Не более 20 тестов, 1 МБ JSON Lines, 32 КБ на stdin или ожидаемый stdout каждого теста. Неизвестные поля, неверные типы и `null` вместо строк отклоняются. Общий timeout упражнения — 100–5000 мс, память — 64–256 МБ. Поля ограничений теста могут переопределять только время, память задаётся упражнением.

В каталоге поле `tests` — строка, содержащая весь JSON Lines. Внешний JSON требует дополнительного экранирования. Используйте [examples/catalog.json](../examples/catalog.json) или экспортируйте каталог через интерфейс, чтобы избежать ошибок. [examples/sum.jsonl](../examples/sum.jsonl) можно скопировать непосредственно в поле «Тесты JSON Lines» формы упражнения.

Отчёт проверки:

```json
{
  "results": [{
    "stdin": "2\n3\n", "expected": "5\n", "actual": "5\n",
    "stdout": "5\n", "stderr": "", "exit_code": 0,
    "duration_ms": 32.4, "timed_out": false, "output_limit": false, "passed": true
  }],
  "lint": [], "passed": 1, "total": 1
}
```

`actual` и `stdout` дублируют фактический stdout для удобства просмотра и совместимости с ответом runner. Замечания Ruff имеют поля `code`, `message`, `location.row` и `location.column`. Все тесты пройдены и замечаний нет → `passed`; все пройдены с замечаниями → `warnings`; хотя бы один не пройден → `failed`; проблема инфраструктуры → `error`. При «Запустить» успешный статус — `executed`, он не влияет на зачёт.

Студент видит первый тест как пример до отправки и все входы/ожидания в отчёте после проверки. Это учебный режим с открытыми тестами, не система скрытых экзаменационных тестов.
