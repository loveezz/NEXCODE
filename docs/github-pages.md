# GitHub Pages

GitHub Pages публикует только frontend. Go, SQLite, Ruff и Docker-исполнитель требуют отдельного сервера. Пока NEXT_PUBLIC_API_URL не задан, сайт явно работает в режиме **предварительного просмотра интерфейса**: демонстрационный каталог, меню, формы и Monaco доступны; настоящего входа, сохранения, выполнения Python и изменения серверных данных нет.

## Публикация

Workflow [.github/workflows/pages.yml](../.github/workflows/pages.yml) собирает и публикует frontend после push в main. В Settings → Pages источником должен быть GitHub Actions. Все действия закреплены по точным commit SHA официальных actions.

Статическая сборка:

```sh
cd frontend
npm ci
npm run build:pages
```

Результат находится в frontend/out, с .nojekyll, локальными Monaco/worker-файлами и страницами с завершающим `/`. Для репозитория NEXCODE по умолчанию base path — /NEXCODE. Упражнения открываются по `/exercise/?id=1`, поэтому произвольные ID не требуют генерации отдельного HTML-файла на каждую задачу.

При другой точке размещения задайте NEXT_PUBLIC_BASE_PATH перед сборкой. Workflow вычисляет её из названия репозитория. Для собственного домена с размещением в корне используйте пустой base path. Обычный npm run build сохраняет серверную standalone-сборку и локальную архитектуру приложения.

## Подключение API позже

Укажите в переменной репозитория NEXT_PUBLIC_API_URL полный HTTPS-префикс API, например `https://api.example.edu/api`, затем перезапустите workflow. Значение входит в публичный JavaScript, секреты в эту переменную помещать нельзя.

Для реального входа нужно согласовать серверную авторизацию: точный разрешённый Origin, credentialed CORS и cookie. Текущие сессии SameSite=Lax рассчитаны на один сайт; предпочтительна связка собственного домена frontend и API одного сайта, например learn.example.edu и api.example.edu. Вызовы с github.io на сторонний домен требуют отдельной настройки авторизации и ограничений third-party cookies. Это не исправляется одной переменной адреса.

GitHub Pages не применяет серверные заголовки и rewrites из Next.js: при необходимости CSP/другие заголовки задаются на отдельном reverse proxy или другой площадке. Старые серверные ссылки `/exercise/1` поддерживаются локальным Next rewrite; на Pages используются query-ссылки.

Секреты, .env, SQLite, логи, конфигурация сотрудников и локальные артефакты исключены из Git. Каталог предварительного просмотра содержит только публичные демонстрационные упражнения.
