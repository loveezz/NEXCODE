# NEXCODE

Полная версия с API и исполнением Python: [развёртывание на Linux-сервере с HTTPS](docs/server.md).

Статический интерфейс можно публиковать на **GitHub Pages**. Пока API не подключён, он работает в явно обозначенном режиме предварительного просмотра. [Публикация и подключение сервера](docs/github-pages.md).

Для **Netlify** добавлены отдельная сборка и netlify.toml. [Настройки и устранение Page not found](docs/netlify.md). При ручной загрузке публикуйте только готовую папку `frontend/out` после `npm run build:netlify`.

Самостоятельно развёртываемая платформа практики Python: Go API, Next.js, SQLite, Monaco, Ruff и изолированные Docker-исполнители. Каталог содержит только четыре работы из папки [practice](practice/): 72 задания с исходной нумерацией, включая письменные алгоритмы, блок-схемы и работу с учебными файлами. [Состав каталога и особенности проверки](docs/practice.md).

## Запуск

Нужен Docker Engine с Compose v2. На Windows используйте Docker Desktop в режиме **Linux containers**.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

Linux / macOS:

```sh
sh scripts/start.sh
```

Откройте **http://localhost:3000**. При первом запуске скрипт создаёт `.env`, генерирует токен исполнителя и пароль администратора. Пароль показывается **один раз в консоли**; на диске сохраняется только bcrypt-хэш `ADMIN_PASSWORD_HASH`. Логин служебного аккаунта — `admin`. Для генерации хэша setup использует Go, если он установлен, либо собирает Docker-образ с вспомогательной командой. Последующие запуски сохраняют конфигурацию.

Если `.env` осталась от версии с `ADMIN_PASSWORD`, setup автоматически заменит открытый пароль bcrypt-хэшем, сохранив сам пароль. Старые `JWT_SECRET`/SMTP-переменные больше не используются. База мигрирует при запуске с резервной копией: [переход с предыдущей версии](docs/identity.md#миграция).

После настройки достаточно:

```sh
docker compose up --build -d
```

## Вход

- **Студенты:** `/login`, только ФИО и группа. Запись создаётся при первом входе; повторный вход с другого компьютера возвращает тот же прогресс. Пароли, почта и регистрация студентам не нужны.
- **Сотрудники:** `/staff/login`, служебный логин и пароль. Учётные записи создаёт администратор через конфигурацию с bcrypt-хэшами, отдельно от ученических профилей.
- **Преподаватель:** раздел «Группы и вход» задаёт **дату окончания семестра**, режим свободного ввода/выбора группы, коды приглашений, просмотр журнала и очистку сессий. Изменение даты обновляет уже выданные серверные сессии; cookie обновляется при следующем запросе браузера.
- **Коды:** для выбранных групп третье поле обязательно. Преподаватель загружает список ФИО + код, в том числе для полных тёзок. Пример: [examples/invites.json](examples/invites.json).

Сессии — непрозрачные UUIDv4 в httpOnly cookie `nexcode_session`, SameSite=Lax, Secure при HTTPS. Несколько сессий разрешены. Выход завершает только текущую сессию. Чужой общий компьютер требует нажатия «Выйти» после занятия. Ученический профиль нельзя повысить до служебной роли: для сотрудников создаётся отдельная запись.

Без кодов любому, кто знает ФИО и группу, доступен соответствующий учебный профиль — это выбранный режим идентификации. Для защиты персональных записей включайте индивидуальные коды в нужных группах.

Подробности и конфигурация сотрудников: [подсистема входа](docs/identity.md).

## Возможности практикума

Каталог, фильтры, прогресс, локально поставляемый Monaco с Python и Ctrl+Enter, запуск с собственным stdin, проверка до 20 тестов JSON Lines, подробные stdout/stderr и замечания Ruff. Черновик сохраняется через две секунды без изменений; дождитесь отметки «Черновик сохранён» перед закрытием вкладки. История отправок хранится без автоматического удаления.

Преподаватель видит прогресс по каждому студенту и упражнению, код отправок, CSV-экспорт, редактор каталога и транзакционный JSON-импорт. Администратор управляет блокировками и служебными ролями, наблюдает очередь, исполнителей и сессии. Светлая/тёмная темы, адаптация для 1024 px и выше.

Новые лабораторные: [examples/catalog.json](examples/catalog.json), [руководство преподавателя](docs/teacher.md), [формат JSON Lines](docs/jsonl.md). Автотесты NEXCODE — внутренний механизм, а не официальные критерии кафедры.

## Исполнение и развёртывание

Только входной `gateway` публикует порт. Он перезаписывает forwarded IP из сетевого соединения; backend доверяет IP-заголовкам только внутри выделенной Docker-подсети. Для другого HTTPS reverse proxy настройте доверенный real IP на gateway явно; не принимайте произвольный клиентский X-Forwarded-For. `WEB_SUBNET` позволяет выбрать подсеть, не конфликтующую с сетью сервера.

API не исполняет Python на хосте и не имеет Docker socket. Доверенный внутренний runner создаёт контейнер на пакет проверки: без сети, read-only, непривилегированный UID, без capabilities, no-new-privileges, лимиты CPU/памяти/PID. Каждый тест исполняется в новом CPython-процессе. Go разбирает JSON Lines и сравнивает вывод. Время теста — до 5 с, память процесса — 64–256 МБ; контейнер ограничен 384 МБ. Python audit hook дополнительно блокирует файловые операции, сеть и запуск процессов. Граница изоляции — Docker/ядро; перед эксплуатацией нужно выполнить контейнерные тесты.

Два воркера и очередь 64 задания по умолчанию; до 15 запусков в минуту на студента. Вход ограничен **10 попытками в минуту на IP**. Сессии и журнал хранятся в SQLite, технический JSON-журнал — `/logs/nexcode.log` в отдельном томе. Планируйте резервные копии БД и ротацию технического журнала.

Для HTTPS задайте `APP_URL=https://...`, `COOKIE_SECURE=true`, нужный `BIND_ADDRESS` и поставьте HTTPS reverse proxy перед gateway. Secure включается также автоматически для HTTPS APP_URL. Origin должен точно совпадать с APP_URL. `APP_TIMEZONE` задаёт часовой пояс окончания учебного дня (по умолчанию Asia/Yekaterinburg).

Для масштабирования исполнителей задайте `WORKERS=4` и запустите:

```sh
docker compose up --build -d --scale runner=2
```

Nginx распределит задания между репликами; каждая принимает два пакета. Backend/SQLite остаётся одним узлом. Не запускайте несколько backend с общим SQLite-томом.

```sh
docker compose ps
docker compose logs -f backend
docker compose down
```

`down` сохраняет тома `database` и `logs`; `down -v` удаляет их. Не копируйте только файл `.db` работающего SQLite без учёта WAL: остановите backend для копирования всего тома либо используйте SQLite Online Backup API.

## Разработка и проверки

Нужны Node.js 24 и Go с автоматической загрузкой закреплённого toolchain 1.27.4. Go не загружает `.env` сам: передайте значения как переменные окружения. Для API нужны RUNNER_TOKEN и конфигурация администратора; для локального просмотра Docker-исполнитель может быть недоступен — ошибки будут показаны честно, локального небезопасного исполнения нет.

```sh
cd backend
go run ./cmd/server
```

В другом терминале:

```sh
cd frontend
npm ci
npm run dev
```

Production: `npm run build`, затем `npm start`. Monaco/worker-файлы копируются при npm ci, CDN не нужен. BACKEND_URL по умолчанию `http://127.0.0.1:8080`; Next rewrite встраивается при сборке. В Docker внешние API-запросы идут через gateway прямо к Go.

```sh
cd backend
go test ./...
go vet ./...
go run golang.org/x/vuln/cmd/govulncheck@latest ./...
```

```sh
cd frontend
npm run typecheck
npm run build
npm audit
npm run test:e2e
```

E2E использует Chrome и запущенные frontend/API на **отдельной тестовой базе**. Для служебных сценариев задайте E2E_ADMIN_PASSWORD. Первый сценарий ожидает исходный свободный ввод групп; следующие меняют настройки и создают тестовые группы. Для повторного полного прогона используйте новую тестовую БД. E2E_RUNNER_AVAILABLE=true включает ожидание успешного исполнения вместо ошибки недоступного runner.

Контейнерные тесты:

```sh
docker build -t nexcode-sandbox:local sandbox
python -m unittest discover -s sandbox -v
```

Без Docker они пропускаются. Производительность 2 с / 10 с и 30 одновременных исполнений нужно подтвердить на целевом сервере. [Архитектура](docs/architecture.md) · [Результаты проверки](docs/verification.md).
